# 桌宠工具集 v1.0.2

一次内容与可用性更新：**宠物叫什么名字，改一处就够**；文案可以单独编辑、带条件占位符；
发行包换成「真正的使用者内容」。

A content and usability release: **rename the pet in one place**, edit her lines on their own page
with conditional placeholders, and a release package that only contains what users actually need.

## 名字与占位符 / Names and placeholders

以前改个名字要挨个去改气泡、对话框开场白、自我介绍，漏一处就前后不一致。
现在名字只有一个来源（`persona.name`），文案里写 `{pet}`，运行时统一替换。

Renaming used to mean chasing every bubble, greeting and self-introduction. Now the name lives in
`persona.name`, copy writes `{pet}`, and the runtime fills it in.

- 变量从 2 个扩到 **23 个**：角色（名字、副名）、来访（连续天数、好感度、饱腹度、被摸次数）、
  时间（时段问候、时分、星期、日期）、页面（标题、标签、分类、字数、预计分钟、阅读进度、评论数…）
- 取值下沉到 `speech` 出口：规则台词、分区反应、检索结果、人设全部生效，写文案不用管谁替换
- 支持条件写法，分支里还能嵌占位符：

```
{title?'读《{title}》':'随便逛逛'}     有值用前段，没有用后段
{tag??'这页没标签'}                    空值才用后备
{!title?'还没打开文章':'正在读{title}'}  取反
```

空串、`0`、`false` 都算「没有」，所以 `{comments?有{comments}条:还没有评论}` 直接可用。
未知变量原样保留（`{nope}` 不会被吃掉），写错名字看得见。

## 文案编辑独立成页 / A page for her lines

`copy-editor.html` 接管 `persona.*` 的全部台词，配置页不再承载文案（只留一轮跳转链接）。

- 跟随右上角语言按钮：中文模式改 `persona.*`，英文模式改 `persona.en.*`，留空即回落默认
- 逐条实时预览，占位符当场展开成句子
- 变量插入收进**一个默认折叠的面板**，点输入框再点变量即插到光标处
- 每条文案独立成卡，中间有蓝条与间距，不再连成一片

## 变量表页面 / Placeholder reference

新增 `vars.html`：写法的六条示例、23 个变量的含义 / 示例 / 取值来源 / 什么时候为空，
点变量名直接复制。清单只有一份（`assets/vars.js`），变量表与文案页都读它，
`tools/manual/check-vars-doc.js` 负责和运行时对账。

## 发行包只装使用者要用的 / A release with no dev content

- 开发侧内容（测试面板、项目状态、开发沿革、已知问题、API 与交互文档）在**打包时删除**，不是运行期隐藏；
  `verify()` 会在产物里发现残留时让构建失败
- 首页 `index.html`，演示 `demo.html`；包内附四个离线编辑器：配置 / 分区 / 规则 / 文案
- 三个编辑器在静态托管下不再连撞 `/api` 404：探不到本地服务就整段跳过，提示可继续导出 YAML

## 顺带修的 / Also fixed

- 发行包缺 `js/pet/site.js`、`js/pet/content/*`、`js/pet-config.json`，导致演示页整条模块链断掉、宠物不显示
- 分区编辑器读不到动作列表（配置 JSON 没进包）
- 表达式实现抽成 `js/pet/content/expr.js`，运行时与编辑器预览共用一份，行为不再漂移
- 文案页漏引 `js-yaml`，打开时静静显示空白

## 升级 / Upgrading

替换 `js/pet/`、`css/`、`images/pet/` 与 `config/pet.yaml` 即可。`config/pet.yaml` 的 `persona` 段
把写死的名字换成 `{pet}` 会更好维护，但不换也能跑——旧配置里的 `{name}` 仍按语境名解释，不会被误替换。

Replace `js/pet/`, `css/`, `images/pet/` and `config/pet.yaml`. Swapping hard-coded names in
`persona` for `{pet}` is recommended; old configs keep working.
